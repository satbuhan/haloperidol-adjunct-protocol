# Choosing an Adjunct to Haloperidol in Hyperactive Delirium with Severe Agitation

An interactive, referenced walkthrough of the decision algorithm for choosing midazolam or
ketamine as the adjunct added to a haloperidol backbone in an adult with hyperactive delirium
and severe agitation (excited delirium syndrome) — from the entry phenotype, through the
withdrawal/age/airway-resource branch points, to reassessment, rescue, and post-sedation care.
Every box and decision point in the diagram can be selected to reveal, in one place: what the
step means, why the algorithm calls for it, and the sources behind it.

**Live site:** https://satbuhan.github.io/haloperidol-adjunct-protocol/

**Authors:** Dr. Özgür Karcıoğlu & Dr. Satuk Buğra Han Bozatlı

## Why this exists

A flowchart alone tells a reader *what* to do at each step but not *why*, and a reader outside
the authors' own team cannot easily check the evidence behind a specific box (why midazolam is
chosen irrespective of speed in withdrawal; why airway resources, not age or aetiology alone,
gate the ketamine option; why the near-direct trial's own effect size sits right at the
boundary of the review's prespecified MCID rather than clearly beyond it). This page keeps the
original algorithm exactly as authored, and attaches the clinical reasoning and literature to
each box without cluttering the diagram itself.

The algorithm this page presents is Figure 2 of "Midazolam versus Ketamine as Adjuncts to
Haloperidol in Excited Delirium Syndrome (Hyperactive Delirium with Severe Agitation): A
Systematic Review of Two Decades of Evidence" — a PRISMA systematic review synthesising 12
comparative studies (n = 2,180) on the adjunct-selection question, from a standalone figure
image supplied directly by the authors.

## Status

This is a working version, built to be tested on both desktop and mobile.

- **Source workflow note:** same external-AI condensation path as `cwa-blood-gas-protocol` and
  `ccb-toxicity-protocol` — the manuscript was run through an external AI (Gemini) using this
  project's structured condensation prompt (`tools/gemini-condensation-prompt.md` in the hub
  repo, v2 — rewritten after an earlier build's output wasn't valid Markdown), and this tool was
  built from that condensed document plus the authors' own standalone Figure 2 image.
- **Reference verification — explicit, author-granted exception (the third in this atlas):** by
  the author's own explicit instruction for this tool, the 74-entry bibliography was **not**
  independently re-verified against primary sources. Dr. Karcıoğlu has already evaluated the
  manuscript's references, and the condensation pass was itself treated as a check, so this
  build's own effort was kept to engineering the tool rather than re-checking citations — see
  `assets/content.js`'s header comment and `METHODOLOGY.md` for the full precedent record
  (alongside `epinephrine-revisited-protocol` and `ketamine-indications-protocol`, the two prior
  tools with this same kind of exception). Every reference's `kind` field says so plainly: "As
  cited in the manuscript; not independently re-verified."
- **Rendering note — the "Rescue" box:** the authors' own Figure 2 loops the Rescue box back up
  to the Reassessment node. This atlas's shared rendering engine only ever draws forward edges
  (a node's bottom to a later node's top), so there is no support for a genuine backward/upward
  loop anywhere in the atlas. "Rescue" is rendered here as a dashed, visual dead end instead —
  the loop-back semantics are conveyed through its own text rather than a drawn arrow.

## Disclaimer

This is an academic / educational reference tool, not a substitute for institutional protocol
or bedside clinical judgement. Doses shown reflect the algorithm as authored; verify against
current local protocol before clinical use. This tool's reference list is reproduced directly
from the source manuscript's own bibliography and was not independently re-verified for this
build — see Status above.

## How it's built

Plain HTML/CSS/JS, no build step and no framework — a single static site that GitHub Pages can
serve directly.

```
index.html          page structure — masthead, the diagram (trunk, three chained decision
                     points each paired with their output box(es), the reassessment convergence,
                     the adequate-sedation/rescue pair, closing post-sedation care), readout
                     panel, references, abbreviation legend, footer
assets/style.css     design (the "paper" masthead/references, the single-trunk diagram grid
                     and its 2-wide/3-wide fan-outs)
assets/content.js     ← single source of truth for every node's text and reference list. Edit
                     this file to change what the page says.
assets/app.js         rendering + interaction (builds the diagram and its connector lines from
                     content.js, handles the click-to-expand panel on desktop and the bottom
                     sheet on mobile; includes a small per-edge detour table so the two
                     adjunct-choice edges that skip ahead to the reassessment node route around
                     the rows in between rather than crossing through them)
```

### Running it locally

No install needed:

```bash
python3 -m http.server 8000
# open http://localhost:8000
```

### Editing content

Open `assets/content.js`. Each entry in `NODES` is one box or decision diamond from the diagram
(`meaning`, `rationale`, optional `cautions`/`dose`, and `refs` pointing at numbered entries in
`REFERENCES`). Add or edit a reference in `REFERENCES` and point to it by `id` from any node.
Never change a node's `label` or `sub` text without the author team's sign-off — those fields
are the algorithm itself, transcribed verbatim from the authors' standalone figure image.
